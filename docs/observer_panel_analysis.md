# SC2 普通对局观察者视野与统计面板

## 目标与约束

目标版本为 SC2 5.0.15.97579（PE 时间戳 `0x6A57F729`，镜像大小 `0x8204000`）。功能用于普通多人或合作对局：保留本地玩家身份和单位控制，同时显示玩家 1、2 的合并地形视野、敌方单位与建筑，以及左上角生产/收入统计。

必须保持以下边界：

- 不修改全局 local player，也不改写单位 owner。
- 战争迷雾透明度保持原值 165。
- 观察者模式与全图视野互斥。
- 保留 `PreserveExploredVisibility`，避免关闭功能后丢失历史建筑、资源、岩石和瞭望塔。
- 仅在显示链需要的位置模拟玩家 16；阵营关系、悬停颜色、命令和 UI 快捷键继续使用真实本地玩家。

## 三种视野模式的区别

三种模式解决的问题不同，不能简单理解为逐级增强。

| 项目 | 旧的全图视野 | 全图视野增强版 | 观察者模式 |
| --- | --- | --- | --- |
| 核心实现 | 将 `0x1CD7A79` 的可见性掩码读取替换为 `0xFFFFFFFF` | Hook `0x1CD7A30` 的单位可见性结果，并主动修改地形迷雾状态 | 使用原生观察者集合和缓存，只在必要显示调用点模拟视角玩家 16 |
| 地形视野 | 不主动重建地形 fog，主要影响单位可见性判定 | 将地形掩码设为 `0xFFFFFFFF`，直接得到全图地形 | 原生合并玩家 1、2 当前视野，未被任何玩家看到的区域仍保留战争迷雾 |
| 迷雾透明度 | 不修改 | 从原值改为 127，使迷雾更透明 | 保持原值 165 |
| 单位与建筑 | 通过全位掩码绕过普通可见性筛选，行为较粗 | 将本地玩家查询结果提升到 8/9 等可见状态，并处理特殊物体 | 对玩家 16 查询玩家集合 `0x6`，使用 `object+0x8E8` 的原生观察者缓存 |
| 信息范围 | 倾向于显示全部实体，但地形效果依赖原有渲染状态 | 地形和实体都按“全开”处理，不受玩家当前视野限制 | 显示玩家 1、2 当前视野的并集，即任一玩家看到的信息，语义接近录像的“所有玩家视野” |
| 玩家身份 | 不修改 | 不修改 | 不修改；仅五个地形/实体显示返回点临时返回 16 |
| 历史信息 | 原始补丁本身不理解 4/5 历史状态 | 受 `PreserveExploredVisibility` 保护 | 同样受 `PreserveExploredVisibility` 保护 |
| 主要用途 | 兼容旧实现、低侵入地放宽单位显示 | 需要真正全图地形及更透明迷雾时使用 | 保持正常战争迷雾，只观察双方实时视野与实体时使用 |

### 旧的全图视野

旧版通过特征扫描定位 `0x1CD7A79`，把原来的可见性表读取替换为 `mov esi, 0xFFFFFFFF`。它只改变单位更新链看到的玩家位掩码，不调用地形设置函数，也不修改 fog alpha。优点是实现简单、改动范围小；缺点是没有使用原生多玩家并集语义，对单位状态和历史可见性的表达较粗，不能等同于录像观察者视野。

### 全图视野增强版

增强版 Hook 单位可见性函数 `0x1CD7A30`。对本地玩家查询，它保留原本已经大于等于 8 的结果；其余普通对象根据单位状态提升为 8 或 9，并对合作任务中的特殊物体单独处理。同时调用 `0x242CFD0` 将地形掩码设为全开，通过 `0x242E240` 设置迷雾参数，最终验证 mask 为 `0xFFFFFFFF`、本地玩家 alpha 为 127。

因此增强版显示的是不受双方当前视野限制的全图信息，视觉上也比正常战争迷雾更透明。它适合“完整揭图”，不适合模拟录像中的“所有玩家视野”。

### 观察者模式

观察者模式复用原生多玩家机制：玩家集合为 `0x6`，`0xA034B0` 合并玩家 1、2 的地形缓冲区，单位链维护 `object+0x8E8` 的观察者缓存。它不写 `0xFFFFFFFF` 地形掩码，也不把普通单位结果统一提升为全图可见，因此双方都未看到的区域和实体不会被无条件揭示。

该模式最关键的约束是局部模拟观察者身份。只有地形输出和单位显示链的五个白名单返回点获得玩家 16；关系、光圈着色、命令和 UI 仍以真实本地玩家计算，所以己方为绿色、中立和盟友为黄色、敌方为红色，且不影响己方单位控制。

菜单可在进入对局前请求观察者模式。此时状态机保持待命，不安装半套 Hook，也不把 Fog state 尚未建立视为永久失败；进入对局并确认地图边界、Fog state 和本地玩家有效后，运行时检查会自动应用。离开对局时先撤销运行态但保留请求，下一局就绪后再次自动应用。

## 左上角统计面板

正确对象是 `CLeaderPanel`，不是右下角 `CObserverPanel`。

当前实现位于 `Dll1/hooks/game_hook_leader_panel.cpp`。

- 工厂：`0xB031F0`
- 构造函数：`0xC22900`
- 根虚表：`0x2B25538`
- 接口虚表：`0x2B25790`
- `IncomeFrame`：对象 `+0x148`，虚表 `0x2B24348`
- `ProductionFrame`：对象 `+0x170`，虚表 `0x2B25018`
- `SelectPulldown`：对象 `+0x130`
- 显示函数：`0x14E48C0`

事件管理器 `SC2+0x443FA40` 的 `+0xD0` 链通过包装回调 `0xC25740` 注册面板。实现沿该链进行最多 256 个节点的有界查找，并核验根对象和两个子控件虚表。开关只修改根面板可见状态，关闭和卸载时恢复原状态。

统计页键盘回调为 `0xC2BA40`。事件类型 `0x18`、动作 `0x12..0x1D` 会切换 12 个统计页；鼠标下拉选择走另一回调 `0xC2C120`。启用统计面板时，MinHook 对前述键盘动作返回原生“未处理”值 1，因此单位快捷键仍可使用，鼠标切换统计页不受影响。

## 安全卸载

按 End 后先设置全局卸载状态，使观察者 detour 立即退化为原函数路径。六个观察者 Hook 通过 `MH_QueueEnableHook` / `MH_QueueDisableHook` 排队，并由一次 `MH_ApplyQueued` 提交，避免逐个启停时反复暂停游戏线程。恢复时先将模式标记为停用并批量摘除 Hook，再通过独立生命周期锁等待在途的单位、视角玩家和 Fog 回调退出，最后恢复 Fog 状态、显示字节和辅助补丁。

## 观察者地形视野

原生录像“所有玩家视野”的关键状态是：视角玩家 16、玩家集合 `0x6`（玩家 1 和 2），而不是全图可见或透明迷雾。

- 迷雾配置：`0xA02A20`
- 玩家集合来源：`0x9569D0`
- 玩家集合辅助函数：`0x568C50`
- 合并迷雾生成：`0xA034B0`
- 合并结果输出判断中的 view-player 返回地址：`0xA035CA`

`0xA034B0` 会按玩家集合筛选并按位 OR 各玩家视野。普通对局中只写入集合和 render player 不够：该函数还调用 view-player getter `0x92BDE0`，只有结果为 16 才把合并结果输出到观察者槽。因此 hook 仅在返回地址 `0xA035CA` 时返回 16，使地形渲染消费玩家 1、2 的合并槽，同时不改变控制玩家和迷雾透明度。

## 单位与建筑显示

单位更新函数 `0x1CE7E60` 的多玩家分支会分别维护：

- `object+0x8D8+player`：各玩家可见性缓存。
- `object+0x8E8`：观察者集合可见性缓存。

观察者查询期间，`HookUnitVisibility` 对玩家 16 使用原生集合 `0x6`。最终显示读取点 `0x1CE80B7` 使用 `object+0x8E8`，并保留 `PreserveExploredVisibility` 的历史状态保护。

仅覆盖单位更新入口仍不够，后续实体显示链也会读取 view-player。当前最小白名单按 getter 的返回地址限定为：

- `0x1CE7E9D`：单位可见性更新选择玩家 16。
- `0x1CE8AA2`：将玩家及集合传给单位可见性查询。
- `0x1CE8FD4`：遍历对象时使用玩家 16 查询可见性。
- `0x1CE90F6`：选择 `object+0x8E8` 观察者缓存。

加上地形返回地址 `0xA035CA`，只有这五处得到玩家 16。其他调用者继续获得真实本地玩家，避免敌方悬停变绿、关系判断变成友军，以及观察者 UI 快捷键抢占单位操作。

## 已确认误区

- **把 `CObserverPanel` 当作统计面板**：它是右下角观察者控制栏；左上角统计属于 `CLeaderPanel`。
- **配置写入成功等于画面生效**：集合、render player 和透明度读回只能证明状态已写入，不能证明最终输出和消费者使用了观察者槽。
- **用透明度或全图补丁模拟合并视野**：原生方案是玩家视野缓冲区按位合并，透明度应保持不变。
- **全局返回 view-player 16**：虽然能显示敌方实体，但会污染阵营关系、悬停颜色、命令和观察者 UI。不能用全局观察者身份替代局部显示白名单。
- **认为绿色敌方对象是 owner 被改写**：代码只读取 `unit+0x40` 做诊断，从未写入 owner；绿色来自关系消费者获得了错误的视角玩家。
- **只覆盖地形和单位更新两个调用点**：后续实体显示链仍按本地玩家过滤，敌方单位和建筑不会完整显示。
- **全局强制单位可见**：会破坏原生 4/5 历史可见状态，导致关闭功能后已探索对象消失。

## 验证状态

普通对局已实测确认玩家 1、2 合并地形视野以及敌方单位、建筑实时显示。全局 view-player 方案随后暴露敌方绿色和 A 键触发观察者统计页的回归；改为上述五处白名单后，用户实测确认问题已修复，己方光圈为绿色、中立和盟友为黄色、敌方为红色，同时保留观察者视野与实体显示。`Debug_observer_scopedview` 构建为 0 警告、0 错误。

观察者模式局外待命、进图自动应用、批量 Hook 启停和两阶段安全卸载均已通过 `Debug_enhanced` 构建。
