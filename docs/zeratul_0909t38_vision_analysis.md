# ZeratulToArtifactII_0909t38_Stable 显示单位分析

## 样本与范围

- 分析日期：2026-09-19；样本来自用户提供的 `F:\BaiduNetdiskDownload\ZeratulToArtifactII_0909t38_Stable`。
- 游戏为 Base97579，磁盘文件版本 `5.0.15.97579`；训练器内部字符串 `5.0.16.97579` 不代表实际游戏文件版本。
- 游戏 PE 指纹：AMD64，TimeDateStamp `0x6A57F729`，SizeOfImage `0x8204000`。
- 依据是此样本的训练器表、Lua 字节码、注入代码、游戏磁盘反汇编与运行时只读内存，不是沿用其他 EXE 的分析。
- 分析阶段没有执行提取出的 Lua 或机器码，没有写游戏内存或替用户切换功能。

## 静态还原

该程序采用 Cheat Engine 训练器封装，运行库文件版本 `7.6.0.8629`。临时目录包含 `CET_Archive.dat`、`defines.lua` 和 `lua53-64.dll`。

1. 归档前四字节是文件数量，其后 raw DEFLATE 解压。逐条读取文件名、目录、长度与内容。
2. `CET_TRAINER.CETRAINER` 为 6,490,766 字节。先从索引 2 前向异或前两字节，再从倒数第二字节逆向异或后一字节，最后异或 `byte(0xCE + index)`；验证 `CHEAT` 头。
3. 头后 raw DEFLATE 解压得到四字节 XML 长度和 7,989,134 字节 XML 正文。
4. LuaScript 的 `decodeFunction` 参数经 CE 自定义 Base85 与 zlib 解码，得到 60,215 字节 Lua 数据；不执行该调用。
5. 定制 Lua 5.3 头的种子低 32 位为 `0x6C34`。每次 LoadBlock 独立计算掩码：块内索引整除 8 时为 `0xCE`，否则为 `(seed >> (index % 14)) & 0xFF`。
6. 指令数组每条 uint32 再减去 `pc % 4`，不是只替换 opcode。规则由样本 Lua DLL 加载函数反汇编核实。
7. 结构解析精确消费全部输入。新版函数为 `root/47`（原脚本行 1201），旧版为 `root/51`（行 1328）。

## 三种实现

以下地址均为相对 SC2 模块基址的 RVA，仅适用于已核验版本。

| 实现 | 位置 | 行为 |
| --- | --- | --- |
| 工程原版 | `0x1CD7A79` | 写入 `BE FF FF FF FF 90 90 90 90 90`，ESI 掩码为 `0xFFFFFFFF` |
| 训练器旧版显示单位 | `0x1CD7A79` | 写入 `BE FF FF 01 00 EB 03`，ESI 为 `0x1FFFF` 并跳过剩余原指令 |
| 训练器新版显示所有单位 | `0x1CD7A30`、`0x235E193` | 函数入口挂钩、`EB 06 90` 补丁，以及定时器中的地形遮蔽和迷雾透明度初始化 |

原版和新版作用于同一函数的不同位置，工程补丁在入口后 `0x49` 字节。原指令为 `lea rcx,[visibilityTable]; mov esi,[rcx+rax*4]`，掩码替换后后续状态判断仍执行。玩家编号 `0x10` 还有绕过这个读取点的原始路径。

## 新版判断

注入代码块位于训练器分配区 `+0x300`。块内 `+3` 是开关，执行入口在 `+52`，`+36` 保存玩家字节地址，`+44` 保存原函数入口后五字节的地址。原入口五字节为 `44 88 44 24 18`。

1. 开关不是 1，或 DL 不等于 `SC2 + 0x3BB8BD0` 的玩家字节：执行原函数。
2. 取 `unit = [RCX + 0x7A0]`；有符号字节 `[unit + 0x41] > 0` 时执行原函数。
3. `[unit + 0x118] & 0x40` 为零时，取 `+0x24` 状态后调用原函数。原 AL 不小于 8 时保留；否则 bit30 为 1 且 bit29 为 0 时返回 9，其余返回 8。
4. `0x40` 位非零时，将 `[unit + 8] & 0x00FFFFFFFFFFFFFF` 与四个标识比较，匹配返回 12，否则返回 1。

四个标识对应 `ZeratulArtifactPickup1`、`ZeratulArtifactPickup2`、`ZeratulArtifactPickup3`、`ZeratulArtifactPickupUnlimited`。目录起点为 `SC2 + 0x3F92168`，经 `+0x2F8` 的目录对象、`+0x48` 的数组读取定义指针。快速槽偏移为 `0x90D0`、`0x90D8`、`0x90E0`、`0x90E8`，失败后按目录数量扫描。名称链为 `[[definition + 0xC8] + 8]`，标识为 `definition >> 5`。训练器还验证 `ZeratulCoop`；整组加载失败时清零四个标识。

### 附加补丁及关闭

`0x235E193` 原代码为：

```asm
mov ecx, [rbx-4]
call SC2+0x242E240
mov esi, 2
```

前三字节从 `8B 4B FC` 改为 `EB 06 90` 后跳到 `mov esi,2`。2026-09-20 通过函数错误标签 `VisSetFoWAlpha` 与最终字节写入确认：被跳过的是玩家战争迷雾透明度设置。该补丁只阻止此调用点后续设置透明度，本身不会初始化透明度。

训练器关闭新版时清零代码块 `+3` 并恢复附加三字节，**保留入口 JMP**。因此仅关闭功能不等于恢复干净游戏进程。

### 定时器中的必要初始化

此前只分析 `root/47` 开关回调，漏掉了 `root/74` 定时器 pc 491-518 的配套步骤。定时器检查第 4 项“显示所有单位”及初始化状态，在达到时间条件后执行：

1. `SC2 + 0x242CFD0(0, false)`：调用 `SC2 + 0x564C20` 将地形遮蔽掩码设为 `0xFFFFFFFF`，随后通过 `SC2 + 0xA00B20` 刷新显示状态。
2. `SC2 + 0x242E240(localPlayer, 204800)`：`204800 = 50 * 4096`，经过定点数转换将该玩家的迷雾 alpha 字节设为 `127`，即约 50%。

定时器随后设置初始化标志，不能误称它每帧反复执行。仅实现可见性返回值挂钩和附加补丁，不等于复现完整“显示所有单位”。

本版本相关状态指针由两个 32 位分量组成，运算均为 uint32 回绕：低位为 `~[SC2+0x3F94B88] + [SC2+0x3EAF0B4]`，高位为 `[SC2+0x3EAD420] + [SC2+0x3F94B8C]`。地形遮蔽掩码位于该对象 `+0x10`，玩家 alpha 数组位于 `+0x20`。这些偏移仅适用于文中 PE 指纹。

## 工程集成

实现位于 `Dll1/hooks/game_hook_vision.cpp` 和 `Dll1/hooks/game_hook_observer_vision.cpp`，GUI 位于 `Dll1/render/menu.cpp`。

- “全图视野”是总开关；旁边“增强版”仅选择实现，默认关闭。总开关关闭时选择模式不应用补丁。
- 增强版使用 C++ 和已有 MinHook 重写已确认的判断及附加补丁，不复制训练器机器码或其他功能。
- 特殊对象由 token 还原定义地址并严格匹配名称，不保存其他进程或上一局地址。与训练器不同，不以泽拉图和整组目录加载成功作为识别前提；名称读取失败视为不匹配。不能宣称是整个训练器生命周期的逐字节克隆。
- 增强版限定上述 PE 指纹，首次核验入口、掩码和附加调用上下文；后续启用仍核验原字节。外部挂钩占用入口时拒绝叠加。
- 2026-09-20 修复补齐上述两次初始化调用，执行前检查三个相关函数入口指令，保存遮蔽掩码及本地玩家 alpha，调用后读回验证 `0xFFFFFFFF` 和 `127`。工程在用户启用时执行，不复刻训练器定时器的延迟条件；对局加载期间启用仍需验证。


### 关闭与卸载

- 取消“增强版”先恢复增强版，再按总开关和地图条件应用原版；恢复失败不切换。
- 关闭总开关先清启用标志，调用 `MH_DisableHook` 恢复入口，核验入口原始 16 字节，再恢复并核验附加三字节。
- 禁用不是删除 MinHook 记录。trampoline 保留至统一卸载，避免模式切换期间立即释放；游戏入口正常恢复后不会再通过该入口进入 detour。
- DLL 卸载先设置卸载状态并禁用所有 MinHook 入口，等待回调门，再恢复直接补丁，最后 `MH_Uninitialize` 和 overlay 清理。
- 新增迷雾状态恢复：关闭、切回原版、初始化失败回滚和卸载均恢复保存的遮蔽掩码及玩家 alpha，并调用显示刷新函数后读回核验。若当前状态对象已更换，不向旧对象地址写入；无法解析或恢复时返回失败。跨局对象同地址复用及地图脚本并发修改尚未验证，不保证覆盖这些生命周期边界。
- 本次核查发现原先失败只记日志仍会 `FreeLibraryAndExitThread`。现已将清理结果向上传递：禁用、补丁恢复或 MinHook 清理失败则中止卸载，保留 DLL 与所需代码并记录错误，需要重启游戏，不再带着未恢复的入口释放 DLL。

## 验证边界

### 2026-09-21 跨地图迷雾重置

- 新增 `UpdateFullMapVisionRuntime`，由已有 D3D9 渲染回调调用，不依赖菜单显示。增强版实际开启时每秒检查状态，遵守总开关、模式选择、地图限制和卸载状态。
- 当前对象、玩家和目标字段均未变化时直接返回，不重复调用游戏函数，也不打印周期计数日志。数据暂不可读时等待后续检查，不向不可读对象写入。
- 状态对象更换或字段被重置时重新设置遮蔽掩码和 alpha。相同对象中未被重置的字段保留原恢复备份，不把本工程写入的目标值反复备份为原值；被游戏重置的字段以新值更新备份。
- 同一对象切换玩家时先恢复旧玩家状态，再备份和应用新玩家状态。关闭时保留已被游戏改成非目标值的字段，避免用旧备份覆盖已观察到的重置。对象同地址复用且字段恰好等于目标值时仍无法仅凭这些字段区分局次。
